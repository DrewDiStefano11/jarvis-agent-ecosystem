## Purpose

Answer, with reproducible evidence:

> Has a local model's performance for a Jarvis role improved, regressed, or remained unchanged after changing model versions, quantization, provider configurations, or evaluation suites?

The offline comparison tool evaluates two previously generated qualification reports (baseline vs. target) without executing models or making network calls.

## Relationship to Qualification Pipeline

The qualification comparison tool operates strictly downstream of model qualification:

```
[Previous Qualification Run] -> baseline JSON artifact \
                                                      -> scripts/compare_model_qualification.py -> comparison report (JSON / Markdown)
[Current Qualification Run]  -> target JSON artifact   /
```

- `scripts/model_qualify.py` generates qualification profiles and run reports.
- `scripts/compare_model_qualification.py` reads existing report artifacts and computes structured diffs and verdicts.

## CLI Usage

```bash
# Basic comparison between two qualification run reports
python scripts/compare_model_qualification.py .local/run1/model-qualification.json .local/run2/model-qualification.json

# Compare specific profiles and output JSON to stdout
python scripts/compare_model_qualification.py profile-qwen3_14b_v1.json profile-qwen3_14b_v2.json --json

# Limit comparison to specific roles or models
python scripts/compare_model_qualification.py baseline.json target.json --role planner --role reviewer --model qwen3:14b

# Write comparison evidence to custom directory
python scripts/compare_model_qualification.py baseline.json target.json --out .local/qualification-comparison
```

### CLI Exit Codes

| Code | Meaning |
| --- | --- |
| `0` | Comparison run completed (even if models regressed or are non-comparable) |
| `2` | Bad usage or invalid/missing input artifact files |
| `3` | Internal comparison tool failure |

## Supported Input Artifacts

The tool accepts any combination of existing qualification output files:

1. **Qualification Run Reports** (`model-qualification.json` generated by `scripts/model_qualify.py`), containing multiple model profiles (`models: tuple[ModelProfile, ...]`).
2. **Individual Model Profiles** (`profile-<model>.json`), containing single model qualification data (`ModelProfile`).
3. **JSON Profile Arrays** (`[ModelProfile, ...]`).

All input payloads are bounded (max file size 10MB) and validated against Pydantic schemas.

## Comparability Rules

To maintain scientific rigor and prevent misleading comparisons:

1. **Inference Mode Integrity**: Fixture evidence (`inference_mode = "fixture"`) is **never** compared numerically against real model evaluation evidence (`inference_mode = "installed_local"`). Mismatches yield `verdict = "non_comparable"`.
2. **Policy Version Matching**: Qualification policy version (`qualification_policy_version`) must match between baseline and target reports.
3. **Evaluation Suite Integrity**: Evaluation suite version (`evaluation_suite_version`) and suite digest (`evaluation_suite_digest`) must match between baseline and target reports.

When an artifact pair fails any comparability check, a `non_comparable` verdict is returned with a clear, explicit reason string instead of computing an arbitrary score delta.

## Verdict Semantics

For each evaluated `(model, provider, role)` combination:

| Verdict | Meaning |
| --- | --- |
| `improved` | Role qualification level improved (e.g. `unqualified` -> `qualified`), OR a previously failing mandatory gate now passes, OR role score increased meaningfully (delta >= `+0.005`). |
| `regressed` | Role qualification level dropped (e.g. `qualified` -> `conditional`), OR a previously passing mandatory gate now fails, OR role score decreased meaningfully (delta <= `-0.005`). |
| `unchanged` | Qualification level, mandatory gates, and advisory gates remained identical, with score delta within threshold (`|delta| < 0.005`). |
| `insufficient_evidence` | Role is missing from baseline or target report, or role qualification status is `not_evaluated`. |
| `non_comparable` | Fixture vs. real mode mismatch, or policy/suite version/digest mismatch. |

## Evidence Reports & Output Formats

By default, the CLI writes comparison evidence to `.local/model-qualification-comparison/`:

- `qualification-comparison.json`: Complete machine-readable Pydantic report (`QualificationComparisonReport`).
- `qualification-comparison-summary.md`: Human-readable Markdown summary tables detailing summary counts, role-level score deltas, and gate-level changes.

Example Markdown comparison table:

| model | provider | role | verdict | baseline level | target level | baseline score | target score | score delta | reason |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `qwen3:14b` | `ollama` | `manager` | **improved** | unqualified | qualified | 0.550 | 0.850 | +0.300 | level improved from unqualified to qualified; score increased from 0.550 to 0.850 (+0.300) |

## Boundaries and Security

- **Observational Only**: Qualification comparison never edits production routing, manager authority, agent models, or coordinator state.
- **Offline & Local**: Performs zero network calls, model executions, or provider calls.
- **Secret Scrubbing**: All free-text reasons and evidence fields are scrubbed to prevent key or credential exposure.
