# Talk to Jarvis and record lookup

The persistent Talk to Jarvis launcher opens a shared command dialog. Ctrl+K or Meta+K toggles it; Find records searches loaded task records, completed result text, registered identities, simulated agents, approval records and existing pages. New request reuses the existing TaskCreateForm, including its API constraints, retry storage, warnings and queued-only acknowledgement. Creating work does not queue a model plan or grant workspace permissions. Planning remains the explicit next step.

Task and simulated agent results use the existing shared inspection drawers. Registered identities are labeled separately: active enabled identities open their existing Planning actor context; other identities open the workforce. This selection does not grant permission. Approval results open the inbox and never approve/reject. Search includes actual identifiers, titles and available descriptions/status evidence; it does not generate answers or interpret commands.

All domain records remain in AppStore and its existing runtime state. Opening the surface refreshes identities through the existing shared loader; there is no additional polling or search backend. Each result group renders at most eight matches and states the matching count/refinement limit. Bounds apply to displayed results, not the existing network collections. This is loaded-record lookup, not a complete server history index.

The form mounts on first engagement and remains mounted across close/reopen and mode changes. Closing during submission does not cancel the request. Accepted-but-lost responses retain the original retry state; after reload identical fields reuse the existing persisted key. Acknowledged success remains visible until the operator explicitly starts another request. Draft text stays in component memory, not local storage, and is lost on reload. Only the existing fingerprint/retry key persists.

Stale/offline Hub state preserves useful lookup, labels last-known data and disables new creation/retry until synchronization recovers. Refresh state uses the existing HTTP fallback. Identity refresh errors remain visible alongside last-known identity records. Explicit local planning and exact workspace approval requirements are unchanged.

Native dialog modality prevents background interaction. Explicit Tab/Shift+Tab wrapping follows document order and visible enabled controls; Escape closes even a nonempty search. Focus restores to the launcher, and the dialog closes before mounting existing inspection drawers. The global shortcut ignores detail dialogs, composing input and repeated key events. Phone controls have at least 44px targets, and the scrollable modal fits 320px-wide and short-height viewports. The launcher sits above mobile navigation, with reserved content padding.

No generated conversation, voice, shell execution, remote control command, cloud fallback or inferred permission is added. Existing surrounding shell remains owned by the separate shell milestone. No new contract, endpoint, migration or domain store is introduced.

Validation: 112 frontend tests, typecheck, ESLint and production build; backend Ruff check/format and two relevant isolated-database API tests. scripts/smoke-command.cjs exercises actual API registration fixtures and identity/task/approval lookup, five widths, native focus wrap/restore, retained drafts, actual queued creation/Planning, failed identity refresh, offline failed HTTP refresh/reconnect, persisted lost-ack retry after reload and closure during in-flight submission. Injected network errors are separated from unexpected browser failures. Model execution stays disabled throughout.
