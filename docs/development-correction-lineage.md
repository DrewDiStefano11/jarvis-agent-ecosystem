# Approved correction workspace lineage

This increment is stacked on #145/#138/#137 and the merged main 5e11d60 native
source/Git foundations. It imports no private provider, publication or validation
implementation. All production model inference remains quarantined.

A completed iteration's acknowledged protected baseline is reference data. The
operator separately creates and approves an owned native destination workspace
for the same durable task and repository/base. PreviewCorrectionWorkspace binds
its original creation authority, protected baseline ID and bounded repair paths.
The preview remeasures a pristine destination while native source/ownership and
metadata pins are held. Advanced or unrelated Git heads refuse until the protected
publication commit/source bridge is integrated.

ApproveCorrectionWorkspace additionally binds the execution actor and exact
preview hash. Actor resolution uses native authentication; the current configured
operator cannot be the executor. The approval persists an append-only lineage,
its own admission/audit/outbox and a native checkpoint in the destination run.
Checkpoint acknowledgement gaps recover that exact approval without source reread
or provider recall. Altered hashes, baseline IDs or repair scopes cannot replay it.
Native creation approval, worker/lease, attempt, RBAC and emergency stop remain
separate live fences. Source effects still require independent exact-plan native
mutation approval.

The task-keyed original admission is unchanged. Each lineage admission inherits
its original provider/model, objective fingerprint, source scope, deletion policy,
request/output limits and admission timestamp. Its elapsed budget cannot restart.
Reservations are counted over every historical workspace for the same task;
unknown outcomes block further correction and allowances are never refunded.
Historical root/response/plan checkpoints are validated as recorded evidence;
they grant no current ownership. The current destination requires its own live
original authority. Lineage ordinals are bounded and must extend the latest
completed baseline, preventing forks or adoption of older work.

Model context joins historical baseline identity, native destination identity and
approved repair scope. Repository/reference contents remain untrusted model data.
Edits validate logical before hashes against the protected baseline; source-plan
compilation uses measured physical destination originals and preserves unmentioned
verified work. The final source-plan transaction rechecks source pins, lineage,
root budget, response identity and live authority. One native mutation per workspace
is retained: correction creates another independently approved owned checkout.

POST /api/development/workspaces/{workspace_id}/correction/preview returns LineagePlan.
POST /api/remote/development/workspaces/{workspace_id}/correction/approve returns
LineageRecord using the existing authenticated secure-transport operator dependency,
registered only with remote control enabled. Requests cannot import historical
snapshots, model responses, observations or validation evidence.

The native two-workspace test uses actual Git/SQLite/runtime/source services and
independent approvals with a deterministic provider. It repairs source.py from the
verified logical value 2 to 3 in a pristine physical value-1 checkout, carries the
previous new.py module, preserves original checkout bytes and retains the original
admission plus both reservations. It is implementation evidence, not real model
quality or Campaign B's independently verified isolated execution.

Remaining integration includes post-publication committed-head bridge consumption,
protected validation diagnosis/repair policy and complete operator task orchestration.
Campaign B's genuine isolated receipts remain required; validation passed and
publication ready are never inferred from these fixtures. Live coding acceptance
requires independently verified included-only subscription use, purchased-credit
exclusion and recharge safeguards. API key use and unverified remote CI remain off.
