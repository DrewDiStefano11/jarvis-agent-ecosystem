# Mission Control metric and interaction contracts

The dashboard measures records from the shared AppStore. It does not equate task records, demonstration activity, identity registration, provider configuration or authorized runtime pages with real AI throughput. Values describe this local Hub and its loaded snapshot, not all Jarvis deployments. Stale snapshots remain inspectable and are qualified by the shell banner and summary scope.

| Visual / KPI | Authoritative source | Definition and aggregation | Scope / provenance | Missing data and interaction |
| --- | --- | --- | --- | --- |
| Open requests | AppStore tasks, `/api/tasks` | Count root records (`parentTaskId == null`) excluding completed, failed and cancelled | Current loaded task snapshot, including demonstrations and operator requests; no time comparison | Unavailable before a confirmed system snapshot. Click filters open root requests in place |
| Completed records | Same task snapshot | Root records whose status is completed | Recorded outcomes, not measured successful model executions | Zero on a confirmed empty snapshot. Click filters completed records; View result opens existing task inspection |
| Pending approvals | AppStore approvals, `/api/approvals` | Count stored pending statuses | Demonstration decision records; expiry, risk, emergency stop and uncertainty still gate individual decisions | Unavailable on initial failed synchronization. Click opens the existing approval workflow in a drawer |
| Registered identities | Shared runtime projection, `/api/identity/agents` via `identityPages` | Count identities after successful retrieval; enabled active count requires both `is_enabled` and active lifecycle | Real registered identities, distinct from simulator agents; registration is not provider or execution readiness | Loading until first successful retrieval; errors show Unavailable instead of zero. Click exposes the direct identity selector |
| Local execution | SystemStatus autonomousWorker, `/api/system/status` | Report enabled state and actual reported worker status; providerReady means configured | Current worker configuration/status, not proof of successful inference | Unknown when worker status is absent. Click opens the real planning workflow without navigating |
| Task distribution donut | AppStore tasks | Each root or child task belongs to exactly one status group: active, queued, waiting, completed, failed or cancelled | Snapshot composition; includes demonstrations; not a success rate | Empty neutral ring with zero records only for a confirmed snapshot. Every legend button filters root/child records in place and can toggle back to All |
| Task progress rings | Each Task.progress | Display validated reported progress, bounded to the visual range | Recorded task progress may represent deterministic simulation; not elapsed effort, utilization or AI progress | Request inspection opens the existing task drawer and preserved results |
| Recorded event bars | AppStore auditEvents, `/api/audit-events` | Deduplicate event IDs, exclude invalid timestamps, group by UTC date, show latest 14 observed dates; recent filters use rolling 7/30-day windows at filter-selection time and exclude future timestamps | Loaded audit snapshot including demonstration events. No completeness claim; absent dates are unknown, not zero events | Explain missing history; never draw synthetic lines. Click a recorded date filters the on-page timeline. Read chart values provides an accessible table |
| System health | SystemStatus and AppStore connection | Report existing API/database/event-delivery states and authoritative blocker counts | Current snapshot, qualified when stale | Unknown health does not imply a healthy installation. Inspection reuses the existing System controls in a drawer |
| Runtime work | Shared runtime actor/task selection, `/api/agent-runtime/runs` with existing actor headers | Display fetched nonterminal runs for selected identity, selected task and authorized pages | Explicitly scoped/paginated; never a system-wide active-run total | No identity prompts direct selection; read failures remain errors; empty pages explain scope; further pages open existing history |

Pending approval records are not native workspace plan authorization. The embedded approval page retains red-risk confirmation, black-risk prohibition, expiry checks, stale-state gates, uncertain-ack reconciliation and server-side authorization. Planning retains its existing task-scoped preparation, exact-plan authorization, provider/worker gates and persisted retry IDs. Merely opening a drawer, selecting a chart filter or selecting an inspection identity never queues inference or grants authority.

The identity count is labeled as a loaded registry snapshot, independently of task/event synchronization. Opening the direct identity selector refreshes that registry. It does not silently treat cached registrations as continuously measured worker availability.

## Unavailable telemetry

Execution throughput, utilization, costs, historical uptime, provider usage trends, fleet-wide workload, source-change validation, PR outcomes and CI success rates remain unavailable unless their authoritative merged contracts supply those measurements. This milestone creates no production endpoints, synthetic histories or placeholder Software Factory actions.

## Visual and interaction acceptance

Primary reference: supplied Mission Control image 1. The second generated concept adapts it to honest first-run state and direct actions. Five concrete iterations address: (1) sparse developer panels with visual KPIs and task rings; (2) absent status visualization with an accessible interactive donut; (3) lost simulation completion evidence with a persistent completed-outcome list; (4) navigation-only calls to action with direct creation/identity selection/inspection; (5) excessive equal-height empty panels and misaligned result rows; (6) mobile long-label overflow; and (7) misleading full-history impressions with explicitly scoped observed-date bars.

The conceptual planet, fabricated reference histories, financial values, example worker identities and unsupported routes are intentional omissions. The implementation uses actual persisted seeded fixtures for QA and no new chart dependency. Full history, costs and real AI throughput await measured telemetry.
