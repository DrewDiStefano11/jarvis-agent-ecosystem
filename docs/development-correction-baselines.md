# Protected correction baselines

Correction compilation preserves the protected captured mode for carried
baseline paths, including mode-only changes and later text edits to those paths.
Newly proposed text outside the baseline inherits the destination's measured
mode, or regular `100644` for a new file. Model text never grants a mode change.
The authoritative status/OpenAPI revision matches the baseline migration head.

This milestone is stacked on Campaign A #138/#137/#133/#130/#128 and the merged
main 5e11d60 source/history/artifact/Git preparation foundations. It imports no
private validation runner, native commit executor or provider implementation.

DevelopmentBaselineService.capture accepts only original native creation
credentials, dispatch identity and an approved native mutation reference. It
requires an acknowledged bound proposal and complete native mutation history,
independently measures current source/artifacts, then reads the bounded original
scope while native source, metadata, ownership and authenticated backup pins are
held. The source CodeState must match both the completed proposal and the native
artifact measurement. Every net changed path must fit the original admission.
Unknown/unselected source, incomplete original identities, drift and substituted
backup inode refuse. No backup is adopted, removed or copied as source content.
The coordination lock must retain its native zero byte; private staging content
is absent from the model source context. Marker/Git-pointer topology stays opaque.

The snapshot retains the exact net after bytes and native original Git identities
in a private development_baselines projection. Its linked transactional audit/outbox
and original runtime checkpoint bind source snapshot, task, dispatch, operator
approval lineage and measurement. Source text and lease credentials never enter
those metadata channels. Context source bytes are captured under final native
transaction guards. A commit/checkpoint gap recovers the same snapshot without
rereading source or repeating a provider request. A replay is historical even when
current files later drift; it is never a source freshness or mutation grant.
Current owner/lease, runtime/RBAC and emergency-stop fences still apply.

POST /api/development/workspaces/{workspace_id}/iterations/{dispatch_id}/baseline
returns a typed BaselineSummary only. Its request accepts native authority and
mutation references, not snapshot payloads, observations or model responses.
Current_source_measured, execution_authorized and validation_passed are false.
Construction opens no provider connection. The new Alembic migration refuses to
drop populated baseline recovery evidence; no application startup create_all exists.

The pure correction compiler joins protected historical baseline identity, native
destination context and bounded repair selection. Logical before hashes are
validated against the captured historical reference; physical before identities
are measured in the destination. It preserves baseline files outside repairs,
restores exact native modes, eliminates physical no-ops, and produces the complete
net intent for independent native source-plan review. It grants no effect and
cannot by itself authorize or persist a correction workspace.

A correction must use a fresh independently approved owned workspace, retaining
the original task's reservation/output/deadline budget. That lineage admission and
actual second-effect workflow remain under implementation. The native single
mutation per workspace is unchanged. Pure destination fixtures test composition;
they do not count as an actual recreated workspace or independent code execution.

Capture occurs before a Git commit advances the original workspace HEAD/index.
Campaign C's exact-head PR observations are reference data and grant no source
or effect authority. A destination based on a publication commit additionally
requires a protected native commit receipt connecting that head to the captured
precommit CodeState. The current pure compiler refuses unrelated/advanced bases;
no private C receipt is silently accepted as an available native capability.
Campaign C dependency coordination has been explicitly authorized by the operator.
Campaign B's real isolated command execution and protected receipts remain required.

All live inference remains quarantined. Native Codex app-server is the preferred
future provider, contingent on independently verified included-only use,

read or used. Standard public GitHub-hosted Actions CI is authorized and required
on the current head. Skipped checks are not passing validation evidence;
