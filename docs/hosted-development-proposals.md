# Hosted development proposals without Ollama

The default-off development executor can produce bounded text code proposals
through Campaign D's existing verified nonbillable HTTP adapters. This grants no
candidate-code execution, source mutation, paid inference or provider activation.
Live model quality and account billing safety still need separate acceptance.

The operator-owned allowance must explicitly declare `code_generation` and
`structured_output` capabilities alongside its exact models, credential
fingerprint, account evidence, expiry, billing exclusions and shared quota.
Existing allowances default to `chat` and `text_generation`. The factory does not
invent coding capability. This route cannot declare tools, vision or shell access.

After separate Campaign D activation and verification, configure:

```text
JARVIS_DEVELOPMENT_ENABLED=true
JARVIS_DEVELOPMENT_PROVIDER=verified
JARVIS_DEVELOPMENT_HOSTED_PROVIDER=<exact configured provider name>
JARVIS_DEVELOPMENT_MODEL=<exact independently verified model>
```

These fields contain no keys and do not activate Campaign D. Generic `openai` and
`codex_app_server` development selections remain unavailable. Local development
retains its original loopback-only controls.

The independent operator reviews the selected source context and exact native
admission plan. `DevelopmentLimits.hosted_route_digest`, generated by
`development_agent.config.hosted_route_digest` for the selected development
provider, binds the endpoint, provider/model, capabilities and complete allowance.
No raw credential enters the digest payload. Changed account/evidence/model
requires new exact-plan approval. A hosted digest and local endpoint cannot be
combined; absent optional fields preserve the historical serialized limit shape.
Exact namespaced IDs such as `vendor/model:free` and `@cf/vendor/model` are
supported only with explicit hosted settings and a hosted admission digest.
Local and historical unbound limits retain their previous model-name constraints.

The separate router has one provider, one physical attempt, no fallback or tools,
and shares durable Campaign D quota. Every dispatch rechecks current activation,
account evidence, credential fingerprint and fixed endpoint alongside RBAC,
leases, admission, runtime and emergency stop. Revocation during awaited health
selection prevents inference. Failed/uncertain requests never refill quota.

Proposal persistence and replay reuse native checkpoints. An acknowledged replay
does not call the model again. Source changes still need independent exact source
approval. Protected validation and publication retain their existing containment
and authorization gates. Deterministic HTTP/native fixtures prove contracts;
they do not establish live inference or a working isolated software factory.
