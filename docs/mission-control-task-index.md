# Mission Control task records

Tasks now provides a compact six-column record index with a phone card layout. Search covers actual title, ID, request, result, status message, error code, direct parent and agent references. View, status, assignment and priority filters intersect; matching subtasks remain visible with direct parent context. Child disclosures and corrected follow-up links use shared task inspection.

All fields come from the existing AppStore tasks, agents and approvals. No additional domain store, polling, endpoint or command authority is introduced. The existing task creation/correction flow and TaskDetails controls are preserved. Root request does not imply a native autonomous goal; records include demonstrations and operator requests. Inspect Planning for native execution and verification evidence.

Active excludes completed, failed and cancelled records. Needs attention derives actual blockers, failure/review/revision states or pending approval records. Blocked uses actual blocker references. Awaiting approval uses waiting_for_approval or matching pending records. Approval counts count records, not authorization or actionability; expiry and workspace plan approval remain in their existing authoritative flows. Retry counts are task-record retries, not native runtime attempt numbers. Progress is reported task progress, not verification.

The index sorts a copied collection by updated timestamp and identifier without mutating shared state. Unknown assignments and missing parent/child/correction records retain identifiers. Status choices remain stable and a selected assignment remains available after its last record disappears. Stale data remains visible with an explicit notice; refresh uses the existing shared HTTP fallback.

Initially 50 matching rows render, with increments up to 200. This bounds rendering, not the existing unpaginated network collection. Completed result previews render inert text up to 4,000 characters, with a truncation notice only when needed. Status summaries show up to 180 characters. Full task records remain available through inspection. No inferred elapsed timers, utilization, model provenance, artifact links or verification rates are displayed.

Validation: 113 frontend tests; typecheck, ESLint and production build; backend Ruff check/format; two focused task/correction API tests against isolated temporary databases. `scripts/smoke-task-index.cjs` uses actual API state and isolated child processes at 1440, 1920, 1024, 390 and 320 pixels. It verifies filters, result preview, task details, creation, corrected follow-up preservation, offline/failed refresh, reconnection and reload. Component coverage additionally verifies subtasks, unknown references, pending versus processed approvals, filter retention, rendering limits and inert/truncated result text.
